T10 RESEARCH · BR-B APPLICATION

웹 서버 로그에서 HTTP 상태코드 유형별 시간 구간 및 경고 임계값 설정에 따른 이상 패턴 탐지 성능 비교

같은 HTTP 오류라도 의미가 다르기 때문에, 상태코드 유형별로 시간 구간과 반복 횟수 기준을 따로 비교한 모의 웹 로그 연구입니다.

이 연구 결과는 이후 HTTP Status Pattern Analyzer의 기본 분석 규칙으로 연결했습니다.

연구 질문을 어떻게 좁혔는가

초기 실험

4xx 전체를 하나의 그룹으로 분석

처음에는 4xx 오류 전체에 동일한 시간 구간과 반복 횟수 기준을 적용했습니다. 이 방식은 단순했지만 401/403, 404, 429가 서로 다른 상황을 의미한다는 차이를 반영하기 어려웠습니다.

최종 실험

상태코드 유형을 분리해 다시 비교

401/403, 404, 429에 5xx까지 추가하고, 각 유형에서 30·60·120초 × 3·5·8·12회를 각각 비교했습니다. 총 48개 조건을 계산해 유형별 차이를 확인했습니다.

실험 규모

4개 유형
401/403 · 404 · 429 · 5xx
1,600개 시나리오
유형별 정상 200 + 이상 200
8,449건 이벤트
고정 난수 시드로 생성
48개 조건
3개 시간 구간 × 4개 임계값 × 4개 유형

이 값은 실제 서비스의 절대적 최적값이 아니라, 연구용 모의 데이터에서 같은 조건으로 비교했을 때 나온 결과입니다.

무엇을 확인했는가

  • 상태코드 유형이 다르면 가장 높은 F1을 보이는 시간 구간·반복 횟수 조합도 달라질 수 있었습니다.
  • 낮은 임계값에서는 탐지율이 높아지는 대신 오탐이 증가하고, 높은 임계값에서는 오탐이 줄지만 일부 이상 시나리오를 놓치는 절충 관계가 나타났습니다.
  • 따라서 하나의 반복 횟수를 모든 HTTP 오류에 동일하게 적용하기보다, 오류의 의미와 정상 발생 빈도를 함께 고려해야 한다고 판단했습니다.

연구 결과를 앱으로 어떻게 옮겼는가

논문에서 숫자만 비교하고 끝내지 않고, 유형별 선택 기준을 실제 로그 분석 기능으로 연결했습니다.

연구 결과 → 유형별 시간 구간·임계값 → 실제 로그 반복 패턴 계산 → 먼저 확인할 Host/IP와 이유 표시

웹 체험판 열기 프로그램 + 예제 다운로드 (ZIP)

연구의 한계

실제 운영 로그가 아닌 모의 웹 로그를 사용했기 때문에 결과를 실제 IDS·SIEM의 공격 탐지 성능과 동일하게 해석하지 않았습니다. 앱 역시 “공격자 확정”이 아니라 반복 오류가 집중된 로그를 먼저 검토하도록 좁혀주는 도구로 설계했습니다.
