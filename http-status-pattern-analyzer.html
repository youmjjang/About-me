HTTP Status Pattern Analyzer

웹 로그에서 같은 종류의 오류가 짧은 시간 안에 반복된 곳을 찾아, 먼저 확인할 Host/IP와 그 이유를 보여주는 로그 분석 도구입니다.

웹 로그 분석이 익숙하지 않은 사용자가 수많은 로그를 처음부터 모두 읽지 않아도 반복 오류가 집중된 대상을 먼저 좁혀 볼 수 있도록 만들었습니다.

웹에서 직접 체험하기프로그램 + 예제 다운로드 (ZIP)연구 보고서 보기

문제

웹 서버 로그에는 정상 요청과 여러 오류가 섞여 있어 처음 보는 사람이 어디부터 확인해야 할지 판단하기 어렵습니다. 그래서 오류의 종류와 짧은 시간 안의 반복 정도를 함께 보고 우선 확인할 대상을 좁히는 방식으로 접근했습니다.

연구 결과를 실제 계산 기준으로 사용

401/403, 404, 429, 5xx를 나누고 30·60·120초와 3·5·8·12회를 조합해 총 48개 조건을 비교했습니다. 모의실험에서 유형마다 가장 높은 F1을 보인 기준이 달랐고, 앱은 이 값을 기본 자동 분석 규칙으로 사용합니다.

앱 동작

1. 로그 입력
Nginx/Apache, CSV, JSON/JSONL
2. 오류 분류
401/403 · 404 · 429 · 5xx
3. 반복 계산
유형별 시간 구간·임계값 적용
4. 우선 확인
Host/IP와 이유·근거 표시

어떻게 개선했는가

개선 전 ① · 연구

4xx 전체에 같은 기준 적용

초기 실험에서는 HTTP 4xx를 하나의 그룹으로 묶어 같은 시간 구간과 반복 횟수 기준을 적용했습니다.

문제: 401/403, 404, 429는 발생 의미가 다른데 하나의 기준으로 분석하면 유형별 차이가 가려졌습니다.

개선 후 ① · 연구

401/403 · 404 · 429 · 5xx로 분리

오류 유형을 나눈 뒤 30·60·120초 × 3·5·8·12회의 48개 조건을 다시 비교했습니다.

결과: 유형마다 가장 높은 F1 기준이 달랐고, 그 값을 앱의 기본 분석 규칙으로 연결했습니다.

개선 전 ② · 앱 UI

Host/IP · 최대 반복 · 임계값 숫자 중심

기술 용어와 숫자가 먼저 보여 처음 사용하는 사람은 “그래서 왜 이 로그를 확인해야 하지?”를 바로 이해하기 어려웠습니다.

개선 후 ② · 앱 UI

이유를 먼저 설명하는 결과 화면

어디에서 어떤 오류가 몇 초 안에 몇 번 반복됐는지 문장으로 설명하고, 주요 경로와 확인 이유를 함께 보여주도록 수정했습니다.

  • 오류가 몰린 시간·주요 경로 표시
  • 판단 근거가 된 로그 확인
  • 분석 결과 CSV 저장

즉, 단순히 화면만 다듬은 것이 아니라 연구 기준 자체를 확장한 뒤 그 결과를 앱 기능과 사용자 설명 방식까지 연결했습니다.
